# Резервная одометрия трамвая: `tram_backup_odometry`

ROS 2 Humble пакет (Python/rclpy), который в реальном времени оценивает **продольную
скорость** и **положение** трамвая по скоростям двух тележек, позиции контроллера водителя
и карте маршрута pathgraph организаторов.

- **Скорость** считается только по тележкам и контроллеру: EKF с моделью тяги и торможения.
  GNSS в оценку скорости не входит ни в одном режиме. С GNSS-коррекцией положения и без неё
  скорость побитово совпадает, это проверяет юнит-тест
  `test/test_gnss_aiding.py::test_bursts_correct_along_track_drift_and_never_touch_speed`.
- **Положение** получается счислением пути вдоль pathgraph с коррекцией по профилю уклона
  (TRN). Вне карты используется геометрия разворотных колец (`maps/loops.json`),
  восстановленная по GNSS обучающих заездов.
- **GNSS для положения.** Начальная привязка к карте делается в стартовом окне (там, по словам
  организаторов, гарантирован RTK). По умолчанию (`gnss_aiding:=true`) нода не отписывается от
  GNSS: редкие пачки фиксов по ходу рейса корректируют положение вдоль пути. Организаторы
  разрешили использовать GNSS для положения без штрафа. `gnss_aiding:=false` возвращает режим
  «GNSS только на старте», в котором подписки уничтожаются сразу после привязки.
- **Точка выхода** — `base_link` эталона организаторов: она лежит на pathgraph на 9.873 м
  впереди master-антенны вдоль пути, z равен z pathgraph.

| вход | выход |
|---|---|
| `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity` (км/ч) | `/result/velocity`: `tram_vehicle_msgs/VelocitySensor`, м/с; оценка на момент stamp − 0.09 с (`output_velocity_delay_s`, см. ниже) |
| `/vehicle/driver_position_cmd` | `/result/position`: `nav_msgs/Odometry`, по умолчанию фрейм `map` (UTM 37N − (300000, 6100000), система карт), точка `base_link`, ковариация положения |
| `/sensing/gnss/{master,rover}/fix`: стартовая привязка, затем (при `gnss_aiding`) пачки фиксов для коррекции положения | `/backup_odometry/diagnostics` (режим `nav_gnss`, `gnss_bursts`, `gnss_rejected`, `pos_eps`), `/backup_odometry/slip` |

Метка каждого выхода — это header stamp входного сообщения, вызвавшего публикацию
(побитовая копия). Выходы идут примерно на 30 Гц (`publish_on:=all`); `publish_on:=cmd` даёт
20 Гц с монотонными метками.

Параметры, которые может понадобиться выставить под систему оценки жюри (подробно в
[docs/JURY_GUIDE.md](docs/JURY_GUIDE.md), раздел 4.1, и в [docs/PARAMETERS.md](docs/PARAMETERS.md)):

| параметр | по умолчанию | назначение |
|---|---|---|
| `vehicle_id` | `30618` в launch (`''` в `params.yaml`) | `30618` / `30639` выбирает масштаб колёс K (3.597 / 3.59); пусто = компромисс 3.595. Скрытая проверка идёт на вагоне 30618, это умолчание launch-файла; для другого вагона `vehicle_id:=30639`, `vehicle_id:=''` берёт значение из файла параметров. `run_bag.sh` и `run_checker.sh` берут номер из префикса имени bag |
| `output_frame` | `map` | `map` / `utm` / `start` / `enu`; для `enu` начало задают `enu_origin_auto` / `enu_origin_lat\|lon\|alt` |
| `output_along_offset_m` | 9.873 | опорная точка вдоль пути от master-антенны: 9.873 = `base_link` (эталон организаторов), 0 = master, 6.22 = середина базы, 12.44 = rover |
| `output_z_offset_m` | 0.0 | выход z = z pathgraph + это значение; 3.10 = высота master-антенны. `z_offset_m` = 3.10 используется только для стартовой привязки GNSS |
| `output_velocity_delay_s` | 0.09 | `/result/velocity` = оценка скорости на момент stamp − 0.09 с (интерполяция по истории). Этот параметр подгоняет выход под эталон, а не описывает физику: twist эталона `/localization/kinematic_state` отстаёт от своей метки примерно на 0.09 с. Значение подобрано на единственном тестовом bag организаторов. 0 = физическая скорость на момент stamp |
| `gnss_aiding` | `true` | коррекция положения по GNSS по ходу рейса; `false` = GNSS только для стартовой привязки |
| `loops_enable` | `true` | геометрия разворотных колец вне карты; `false` = старый мост/хвост |

Launch-файл пробрасывает только `vehicle_id`, `output_frame`, `maps_dir`. Остальные параметры
задаются своим `params_file:=...` или через `ros2 run ... --ros-args -p имя:=значение`
(JURY_GUIDE, раздел 4.1). Опечатка в значении перечислимого параметра останавливает ноду при
старте с `ValueError`.

## Быстрый старт

```bash
./scripts/build.sh                                   # Docker-образ + офлайн colcon build (--network none)
./scripts/run_bag.sh ../dataset/data/30618_0e41eac3 /tmp/run1 --duration 120 && cat /tmp/run1/check.txt
```

Проверка на тестовом bag организаторов их же checker'ом:

```bash
# ROS checker организаторов (hackathon_solution_checker) в Docker, весь bag (1309.6 с) в реальном времени
./scripts/run_checker.sh ../check_code/check-code/bags/30618_88aea4d9 /tmp/chk --measure && cat /tmp/chk/checker_final.txt
# офлайн-эмуляция того же checker без ROS (тот же Pipeline, варианты с отключёнными функциями)
# все 7 вариантов (6 штатных + GNSS только первые 35 с), как в results/checker_30618_88aea4d9/summary.md
OMP_NUM_THREADS=1 python tools/checker_sim.py --gnss-start-only 35 --out /tmp/chk_sim
```

Вручную, в собранном workspace или в контейнере `tram_backup_odometry:humble`:

```bash
ros2 launch tram_backup_odometry backup_odometry.launch.py vehicle_id:=30618   # 30618 | 30639: префикс имени bag
ros2 bag play <dataset>/data/30618_0e41eac3
# без GNSS-коррекции по ходу рейса (GNSS только на старте):
ros2 run tram_backup_odometry backup_odometry_node --ros-args \
    --params-file "$(ros2 pkg prefix tram_backup_odometry)/share/tram_backup_odometry/config/params.yaml" \
    -p vehicle_id:=30618 -p gnss_aiding:=false
```

Юнит-тесты на хосте: `python -m pytest -q src/tram_backup_odometry/test` (106 passed,
12 skipped); в образе `RUN_TESTS=1 ./scripts/build.sh` — 120 passed, 11 skipped.

### 2. Кросс-валидация на 60 заездах

Офлайн-реплей того же `Pipeline` на всех 122 bag, 0 ошибок. Метрики считаются по 60
уникальным bag с ≥ 60 с RTK-эталона. Эталон — master-антенна: CV-инструменты
(`tools/run_cv.py`) принудительно ставят `output_along_offset_m` = 0, z + 3.10 и
`output_velocity_delay_s` = 0. Сопоставление по header stamp ±0.05 с, гейт 5 м.

- `F3_final` — версия до колец и GNSS-коррекции, GNSS первые 10 с.
- `F4_final` — текущий код, GNSS первые 10 с. Коррекции по ходу рейса здесь нет, разница с
  F3 даёт в основном кольца (и якорь по стартовому окну GNSS).
- `F4_final_burst` — текущий код, GNSS первые 30 с и далее пачка 1.5 с каждые 120 с. Это
  имитация редкого GNSS по ходу рейса.

  1.90 → 3.60 м, `30639_92226df0` 15.9 → 17.6 м.
- Числа F4 сняты после исправления 27.09 в `Pipeline._process_burst`: раньше пачка GNSS в
  стартовом окне (до запуска TRN) оставляла TRN-смещение якоря пустым, и TRN до конца
  рейса не корректировал выход. Тогда у F4_final было 2.38 / 4.32 м along-track и
  2.14 / 4.00 м e3d. Подробности — [docs/RESULTS.md](docs/RESULTS.md) и
  [docs/MODEL.md](docs/MODEL.md), §9.
- При пачках GNSS ковариация местами занижена: среднее NEES 4.69, доля эталона внутри
  95 %-эллипса в среднем 0.93.
- **Оговорка по утечке.** Геометрия колец построена по тем же обучающим заездам, на которых
  идёт CV. Поэтому числа «вне карты» и все, что от них зависят (e3d, дрейф в конце), у
  F4_final и F4_final_burst оптимистичны. Честная проверка колец — тестовый bag
  организаторов, которого не было в обучении (раздел 1).

- **Скорость на чистых данных.** Кинематический фильтр почти догоняет модель по медиане

  Отказ одной тележки не заметен по точности. Источник: `results/robustness/summary.md`,

### 4. Устойчивость

Источник: `results/robustness/summary.md` (`tools/robustness.py`, текущий код, GNSS первые
10 с).

- 336 прогонов с отказами (12 заездов × 28 сценариев): 0 падений, 0 прогонов с нечисловыми
  выходами, 0 отрицательных скоростей.
- Все выходы несут штамп входного сообщения.
- На 122 bag `F4_final`: 0 ошибок, 0 нечисловых скоростей и поз, 0 отрицательных скоростей.
- Несогласованные пачки GNSS (например, фиксы в 30 м от пути) отклоняются, это проверяет тест
  `test_inconsistent_burst_rejected`. На тестовом bag отклонена 1 пачка из 50.

Найденные слабые места перечислены в разделе 4 сводки устойчивости и в
[docs/LIMITATIONS_ROADMAP.md](docs/LIMITATIONS_ROADMAP.md):

- после 15 с полного молчания входов первый выход несёт состояние до паузы;
- неверно обрабатывается конец синфазного боксования обеих тележек; при синфазном юзе −30 %
  путь не лучше наивного;
- нет онлайн-оценки отношения масштабов тележек;
- «замёрзшая» команда смещает адаптивные коэффициенты;
- экстренное торможение вне контроллера не видно в `adhesion_used`.

## Основные ограничения

Полный список — в [docs/LIMITATIONS_ROADMAP.md](docs/LIMITATIONS_ROADMAP.md).

- **Ветвь кольца без GNSS по ходу рейса.** Без GNSS хвост кольца по умолчанию идёт по ветви A.
  Тестовый bag заканчивается на ветви B кольца T, поэтому в последней минуте при GNSS только на
  старте ошибка 30 м.
- **Геометрия колец** — центральная линия по GNSS обучающих заездов. Для T/B (двойной путь)
  разворот не наблюдался, вместо него стоит заглушка.
- **Утечка в CV.** Кольца построены по тем же заездам, что и CV, поэтому числа «вне карты» у
  F4 оптимистичны.
- **Часы GNSS.** Метки GNSS-фиксов сопоставляются с часами колёс. Сдвиги часов GNSS около 1 с
  есть в 7 из 60 заездов, и пачка с таким сдвигом ложится не на тот отсчёт одометра. Ошибку
  ограничивают гейты и проверка разброса.
- **Задержка скорости 0.09 с** подобрана на единственном тестовом bag организаторов.
- **Замечания по устойчивости** — раздел 4 `results/robustness/summary.md`.
