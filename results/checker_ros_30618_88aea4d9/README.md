```bash

scripts/run_checker.sh ../check_code/check-code/bags/30618_88aea4d9 results/checker_ros_30618_88aea4d9 --measure
```

Что делает `scripts/run_checker.sh` (один контейнер, `--network none`, bag и исходники чекера смонтированы read-only):

- копирует `check-code/src/checker_ros` в `/tmp/chk/src` и собирает только `hackathon_solution_checker`
  (`colcon build --packages-select`) поверх `/ws/install`, т.е. против **нашего** `tram_vehicle_msgs`
  (`VelocitySensor` идентичен их копии); лог — `checker_build.log`, сборка без ошибок;
- запускает узел: `ros2 launch tram_backup_odometry backup_odometry.launch.py use_sim_time:=false vehicle_id:=30618`
  (параметры по умолчанию: точка вывода base_link, кадр map, GNSS-коррекция включена);
- запускает чекер с параметрами по умолчанию (sync_tolerance_sec 0.05, queue 100), рекордер
  `/result/*` + воспроизводимого `/localization/kinematic_state` (`result_bag/`), `latency_probe.py` и `resource_monitor.py`;
- `ros2 bag play /data/bag -d 1 -r 1.0` (1311 с), пауза 3 с, SIGINT чекеру — он печатает финальную сводку
  при остановке (`checker_final.txt/.json`; если бы её не было, взялся бы последний 5-секундный отчёт с пометкой).

Позиция совпадает до третьего знака, число пар — с точностью до 4 (0.01 %). Разница в скорости (−0.0013 м/с)
объясняется не синхронизацией, а самими выходами:

- эмуляция синхронизатора (`sync_pairs` из checker_sim) на записанных в этом прогоне временах прихода
  (`result_bag/`, включая воспроизведённую эталонную тему) даёт velocity 0.032197 / max 0.308957 — ровно как чекер —
  и 3D 1.1162 / max 14.030 (n 38439): эмулятор чекера подтверждён;
- у ROS-узла 12.5 % выходов (4820) имеют другой стамп, чем офлайн, а у совпадающих стампов скорость отличается
  в среднем на 0.006 м/с (p99 0.048, max 0.27), позиция — на сантиметры (до 1.1 м только в первые 10 с при
  стартовом «залпе» сообщений). Причина — порядок обработки почти одновременных сообщений передней и задней тележек:
  офлайн-воспроизведение идёт строго по времени записи, а executor rclpy обрабатывает готовые подписки в своём порядке,
  поэтому триггером выхода становится то одна, то другая тележка. На точность это не влияет систематически:
  по ближайшему эталону (±0.05 с) RMSE скорости ROS 0.0327 против 0.0339 офлайн.

Сравнение выполнено скриптом `.work/compare_ros.py` (запуск в образе: он импортирует `tools/checker_sim.py`).
