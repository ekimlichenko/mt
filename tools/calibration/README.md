# Калибровка параметров оценщика (`tools/calibration/`)

Здесь собраны скрипты, которые показывают, откуда взялись значения параметров модели. Все параметры
заданы в одном классе `Params` в `src/tram_backup_odometry/tram_backup_odometry/core/config.py`.
Те же имена используются в `config/params.yaml` и в `docs/PARAMETERS.md` (§5: полный список с
колонкой «происхождение»).

Параметры попадают в одну из трёх групп:

1. **Измерены по данным** (§3). Скрипт считает статистику или подгонку прямо по записям
   (колёса, GNSS RTK, команды, карта), и значение в `config.py` равно результату или округлено от него.
2. **Подобраны сквозным CV** (§4). Эти параметры не наблюдаются напрямую (масштаб колеса 30639,
   параметры TRN, фактор касательной моста). Значение выбрано полным прогоном конвейера
   (replay, затем оценка как у жюри) по сетке значений на 60 оцениваемых бэгах (или на их части по вагону / направлению), с проверкой
   leave-one-group-out по дням вагона. Для каждого значения показано, насколько плоское плато вокруг него.
3. **Инженерный выбор** (§6). Это защитные границы, горизонты и шаги без скрипта по данным.

## 1. Запуск

Все пути задаются относительно корня решения (родитель `tools/`), так что скрипты запускаются из корня:

```bash
cd solution
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
PY=python3          # любой python 3.10+ с numpy, scipy, pyyaml
$PY tools/calibration/<script>.py --help         # у каждого скрипта есть docstring и --help
```

| Что | Где | Чем строится |
|---|---|---|
| кэш бэгов (topic -> numpy) | `.work/cache/<bag>.pkl` | `tools/build_cache.py` |
| индекс бэгов (eval_ok, rtk_frac, фолд = день вагона) | `.work/bag_index.json` | `tools/bag_index.py` |
| датасет (только `metadata.yaml`) | `../dataset/data/<bag>/` | исходные данные |
| карты маршрутов | `src/tram_backup_odometry/maps/{t2s,s2t}.json` | в пакете |
| результаты калибровки | `$CALIB_WORK/<шаг>/` (по умолчанию `.work/calibration/<шаг>/`) | эти скрипты |

- Скрипты импортируют только `core/*` пакета, ROS 2 им не нужен. Общие пути и помощники лежат в `_common.py`.
- Параметры строятся так же, как в `tools/run_cv.py`: значения по умолчанию, затем `--params yaml`,
  затем `--set k=v`. `vehicle_id` берётся из имени бэга.
- Параллельность задаётся `--jobs N` (по умолчанию 4). Пул процессов на macOS (spawn) защищён `if __name__ == '__main__'`.
- Контрольные прогоны для этого README сделаны с `CALIB_WORK=.work/scratch_deliv/calib`. Там лежат все
  упомянутые ниже `summary.json` / `*.json` и логи `sweep_*.log`.

## 4. Параметры, подобранные сквозным CV

`cv_sweep.py` перебирает один параметр. Остальные остаются как в `config.py`, конвейер тот же, что в
`tools/run_cv.py`: replay, GNSS только первые 10 с, эталон RTK master, `tools/evaluate.py`. В таблицах:
`score_loss` (среднее / медиана по бэгам; меньше — лучше), `al_rmse` (СКО ошибки вдоль пути, м),
`p_in95` (доля в 95 %-эллипсе ковариации), разница среднего `score_loss` с лучшим значением в сетке.
Строка текущего значения выделена. LOGO: значение выбирается на 5 днях вагона из 6 и оценивается на
шестом. Показано, сколько раз выбрано каждое значение.

```bash
$PY tools/calibration/cv_sweep.py --param <поле Params> --values v1,v2,... [--bags 'eval&dir:T2S'] --cv --jobs 4
# эквивалент через run_cv:  $PY tools/run_cv.py --tag <tag> --bags eval --jobs 4 --set <поле>=<значение>
```

Сводка (подробные таблицы ниже; «плато» — диапазон, где mean score_loss хуже лучшего не больше чем на ~0.5 %):

| `trn_corr_len_m = 20` (темперирование коррелированных отсчётов) | 10: 1.503, 15: 1.490, **20: 1.486**, 30: 1.491, 40: 1.507 | ≤ 1.4 % | 20 ×3, 30 ×2, 10 ×1 |

Все три плато плоские (±50 % от значения меняют score_loss меньше чем на 1.5 %). У `trn_trunc` 0.2 и 0.3 неразличимы (0.04 %).

Более ранний модульный перебор TRN проводился отдельной оценкой ошибки пути вдоль маршрута без полного
конвейера (464 прогона-окна, `.work/scratch_trn/{sweep,cv,evalrun}.py`, итог `.work/scratch_trn/final_grid.txt`).
Он дал исходную точку `trn_sigma` 0.065, lookahead 10/10, `trn_corr_len_m` 20, `trn_trunc` 0.3,
`trn_grade_window_m` 9, `trn_eps_range` 0.015, `trn_eps_prior` 0.004. На карте MAE апостериорного
среднего 5.86 м против 22.72 м без TRN, покрытие 2σ 0.966. Этот каркас не перенесён в `tools/calibration`:
в нём жёстко прописаны пути и собственная копия ядра TRN. Окончательные значения проверены сквозным
`cv_sweep.py` на итоговом коде (таблицы выше).

### 4.3 Ковариация позы (`pose_trn_sigma_scale = 0.6`, `pose_sigma_cross_m = 0.8`)

Ковариация не влияет на оценку. Поэтому `covariance_consistency.py` один раз прогоняет 60 бэгов,
раскладывает опубликованные дисперсии по формулам `Pipeline._output` (`core/pipeline.py`) и
пересчитывает их для сетки масштабов без повторного прогона. Ошибка восстановления текущих дисперсий
составляет 3e-16 (относительная). Сопоставление с эталоном то же, что в `tools/evaluate.py`.

```bash
$PY tools/calibration/covariance_consistency.py --bags eval --jobs 4 --scales 1,0.8,0.6,0.5,0.4 --cross 0.3,0.5,0.8,1.0
$PY tools/calibration/covariance_consistency.py --reuse --scales ... --cross ...    # без повторного прогона
```

Результат: 60 бэгов, 651 731 сопоставленная точка.

| scale / cross | на карте: доля в 95 % | NEES | по бэгам p_in95 (медиана / среднее) | бэгов с p_in95 < 0.7 | NEES по бэгам (среднее) |
|---|---|---|---|---|---|
| 1.0 / 0.3 (было) | 0.928 | 3.65 | 0.986 / 0.926 | 5 | 5.30 |
| 1.0 / 0.8 | 0.963 | 0.60 | 0.998 / 0.964 | 1 | 0.90 |
| 0.8 / 0.8 | 0.960 | | | | 0.95 |
| **0.6 / 0.8** | **0.954** | **0.78** | 0.998 / 0.956 | 2 | 1.05 |
| 0.5 / 0.8 | 0.933 | | | | 1.15 |
| 0.4 / 0.8 | 0.922 | 1.13 | 0.996 / 0.930 | 4 | 1.34 |

- Вдоль пути. Нормированное апостериорное СКО TRN примерно в 2 раза шире реальной ошибки:
  rms(e_along / std) = 0.45, робастно 0.31. Масштаб 0.6 даёт долю 0.954, ближайшую к 0.95, и NEES ближе всего к 1.
- Поперёк пути. На карте |cross| в 90 % случаев не больше 0.35 м. Но на S2T трамвай иногда идёт по
  параллельному пути примерно в 4 м от графа: p95 1.04 м, p99 4.2 м. Значение 0.3 это не покрывает, 0.8 покрывает.
- Бэги с p_in95 < 0.7 при выбранных значениях: `30639_92226df0` (0.52) и `30639_9c362687`
  (0.58, медиана |cross| на карте 8.5 м, это параллельный путь).

## 6. Параметры без скрипта по данным (инженерный выбор)

Для этих параметров нет калибровочного расчёта. Обоснование каждого дано в `docs/PARAMETERS.md` (§5, колонка «происхождение»).
