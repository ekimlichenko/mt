МАТЕМАТИЧЕСКАЯ МОДЕЛЬ РЕЗЕРВНОЙ ОДОМЕТРИИ

Оценка одномерна — вдоль рельса. Скорость v и путь s оценивает расширенный фильтр Калмана (EKF): прогноз даёт физическая модель тяги и торможения по позиции контроллера с учётом уклона и кривизны карты, измерение — скорости двух тележек. Положение, высота и курс берутся из геометрии пути в точке s.

1. СТРУКТУРА (цепочка на каждое входное сообщение)
1) TimeGuard — проверка header-меток (скачки, опоздания, некорректные метки).
2) WheelFusion — перевод в м/с, отбраковка выбросов, слияние тележек, детектор боксования и юза.
3) Модель тяги и торможения (Хаммерштейн): задержка → статическая карта a(n, v) → звено первого порядка.
4) EKF с состоянием x = [v, b, g_tr, g_br, s]ᵀ.
5) Путь прогона RunPath: голова (ветвь разворотного кольца из maps/loops.json или G1-мост — кубическая кривая Эрмита с непрерывным курсом) + карта pathgraph + хвост (ветвь кольца; без колец — затухающая кривизна).
6) TRN (terrain-referenced navigation) — привязка к профилю уклона: сравнение ускорения по колёсам с модельным даёт поправку положения вдоль пути.
7) Initializer — выставка по GNSS в стартовом окне (3 с после первого фикса, тайм-аут 10 с): маршрут, привязка одометра к карте, начальная СКО σ₀.
8) GNSS-коррекция (gnss_aiding, по умолчанию включена) — пачки фиксов после выставки сдвигают только положение вдоль пути.

2. ВХОДНЫЕ ПЕРЕМЕННЫЕ
• raw_F, raw_R — скорости передней и задней тележек (/vehicle/{front,rear}_bogie_velocity), км/ч, около 9.36 Гц.
• n — позиция контроллера (/vehicle/driver_position_cmd), целое −15…+15: n > 0 тяга, n < 0 торможение, −8 — удержание скорости; около 20 Гц.
• t — header stamp сообщения, с.
• Фиксы GNSS (/sensing/gnss/{master,rover}/fix) — только выставка и опциональная коррекция положения.
• Карта: pathgraph двух направлений T2S и S2T (x, y, z, кривизна κ) в системе map = UTM 37N минус (300000, 6100000) м; кольца maps/loops.json.

3. ВЫХОДНЫЕ ПЕРЕМЕННЫЕ
• /result/velocity: v, м/с — оценка на момент t − 0.09 с; метка выхода = метка входа.
• /result/position (nav_msgs/Odometry, кадр map): x, y, z, м — точка base_link в 9.873 м впереди главной антенны, z — высота пути; курс ψ, рад; twist.linear.x = v; ковариация позы C_xy = R(ψ)·diag(σ_al², σ_ct²)·R(ψ)ᵀ (σ_al — вдоль пути, σ_ct — поперёк), σ_z² = 0.25 м², σ_ψ²; дисперсия скорости P_vv.
• Диагностика: ускорение a, м/с², сцепление |a|/g, усиления, смещение; флаг проскальзывания.

4. КОЛЁСНОЕ ИЗМЕРЕНИЕ
v_F = raw_F/K при raw_F > 0, иначе 0 (так же v_R). K ≈ 3.6 объединяет перевод км/ч → м/с и ошибку радиуса колеса; калибровка по RTK: 3.597 (вагон 30618), 3.59 (30639), 3.595 по умолчанию.
При согласии |v_F − v_R| ≤ max(0.2; 0.03·max(v_F, v_R)) м/с измерение z = (v_F + v_R)/2, σ_m = 0.03 м/с; одна тележка — 0.045; расхождение — тележка, ближайшая к последней согласной скорости, σ_m = 0.35 и флаг проскальзывания; две тележки на одну метку — σ_m·√2. Синфазный тест: наклон z за ≥ 0.3 с вне [−6.0; +2.5] м/с² поднимает флаг.

5. МОДЕЛЬ ТЯГИ И ТОРМОЖЕНИЯ
Задержки: n_tr = n(t − 0.05 с), n_br = n(t − 0.15 с).
Тяга (n > 0):
  a_tr(n, v) = min( b₀ + a₀·n/(1 + max(v − v₁, 0)/v_a) ; A₀·min(1, v_b/max(v, 10⁻³))^p_w ) − r₀,
  b₀ = 0.0968 м/с², a₀ = 0.1131 м/с², v₁ = 3.49 м/с, v_a = 6.90 м/с, A₀ = 1.048 м/с², v_b = 5.90 м/с, p_w = 0.571, r₀ = 0.04 м/с².
Служебное торможение (n < 0, n ≠ −8):
  a_br(n, v) = max( −(d₀ + d₁·|n|)·(1 − f·exp(−v/v_f)) ; a_cap ) − r₀,
  d₀ = 0.193 м/с², d₁ = 0.1123 м/с², f = 0.327, v_f = 2.98 м/с, a_cap = −1.7 м/с².
Позиция −8 (удержание): a = 0 при v > 2.5 м/с, иначе −0.85 м/с².
Инерция (точно на подшаге Δt): z_k ← z_k + (1 − exp(−Δt/τ_k))·(u_k − z_k), k ∈ {tr, br}; u_tr = a_tr(n_tr, v), u_br = a_br(n_br, v), τ_tr = 0.25 с, τ_br = 0.30 с.
Привод: a_ng = g_tr·z_tr + g_br·z_br − r₀·[нет ни тяги, ни торможения].
Полное ускорение:
  a = a_ng + c·g·γ(s_g) − k_c·|κ(s_g)| + b,  s_g = s_off + δ_app + s + ℓ — точка карты для уклона и кривизны,
g = 9.81 м/с²; γ = dz/ds — уклон карты по ходу (сглаживание 31 м); c по режиму: тяга −0.886, торможение и −8 −0.812, выбег −0.978 (физически −1); k_c = 3.0 м²/с²; κ — кривизна, 1/м; ℓ = 12 м (T2S) / 10 м (S2T) — точка уклона впереди антенны. Вне карты γ = κ = 0.
Защёлка стоянки: при v < 0.05 м/с и стоящих колёсах a = 0, пока тяга не продержится 1.2 с.
Табличная карта с задержками, уклоном и кривизной подобрана МНК на 68 записях (RMSE ускорения 0.163 м/с² против 0.205 у одной статической карты); формулы её аппроксимируют.

6. ОТ МОМЕНТА К УСКОРЕНИЮ И СКОРОСТИ
Физически a = (M(n, ω)·i·η/r_w − F_res)/m − g·γ: M — момент, i — передаточное число, η — КПД, r_w — радиус колеса, F_res — сила сопротивления, m — масса, ω = i·v/r_w. Момента, тока и массы во входах нет (команда несёт только позицию int8, датчик тележки — только скорость), поэтому сомножители не разделяются: карта a_tr(n, v) идентифицирована сразу в единицах ускорения как удельная сила привода M·i·η/(r_w·m). Зависимость момента от ω — это зависимость карты от v: полка b₀ + a₀·n, потолок A₀ и его спад (v_b/v)^p_w (p_w = 1 соответствовало бы постоянной мощности). Сопротивление (r₀), кривые (k_c·|κ|) и уклон (c·g·γ) — отдельные слагаемые. Отклонение массы рейса поглощают оцениваемые усиления g_tr, g_br и смещение b; радиус колеса в одометрии входит в K. Далее EKF интегрирует ускорение, v' = v + a·Δt (раздел 7), и корректирует скорость по колёсам.

7. ФИЛЬТР EKF
Состояние: v, м/с (v ≥ 0); b — смещение модели, м/с², Гаусс–Марков (τ_b = 10 с, σ_b = 0.05 м/с²); g_tr, g_br — усиления, случайное блуждание σ_g = 0.002 1/√с, ограничены [0.8; 1.3]; s — одометр, м.
Прогноз на подшагах Δt ≤ 0.05 с:
  v' = v + a·Δt,  s' = s + (v + v')·Δt/2 (при v' < 0: s' = s + v²/(−2a), v' = 0),  b' = φ·b,  φ = exp(−Δt/τ_b).
Якобиан: F_vb = Δt, F_v,g_k = z_k·Δt, F_bb = φ, F_sv = Δt, F_sb = Δt²/2, F_s,g_k = z_k·Δt²/2.
Шум: q = σ_a²·T_c, T_c = 1 с; Q_vv = q·Δt, Q_vs = q·Δt²/2, Q_ss = q·Δt³/3, Q_bb = σ_b²·(1 − φ²), Q_gg = σ_g²·Δt; σ_a: тяга 0.11, выбег 0.16, торможение 0.085, n ≤ −9 0.43, −8 0.6, без свежей команды 0.5 м/с². P ← F·P·Fᵀ + Q.
Обновление: H = [1 0 0 0 0], y = z − v, S = P_vv + σ_m², k_i = P_iv/S, x_i ← x_i + k_i·y, P_ij ← P_ij − P_iv·P_jv/S. До обновления z ограничивается темпом: [v_p − d·Δt_p; v_p + 1.8·Δt_p], d = 6.0 м/с² при согласных тележках, 2.4 при проскальзывании. Усиления адаптируются только при согласных тележках без проскальзывания и y² ≤ 9·S (гейт 3σ). На подтверждённой стоянке v = 0, P_vv = 0.01².

8. КАК ОЦЕНИВАЕТСЯ УСКОРЕНИЕ
– Прогноз: a считает модель раздела 5 по n, v, уклону и кривизне в текущей точке карты.
– Коррекция: невязка колёсной скорости через ковариации P_bv, P_gv исправляет b, g_tr, g_br — модельное ускорение подстраивается под рейс. Колёса в EKF не дифференцируются.
– Выход: итоговое a экстраполирует состояние к метке выхода, v_e = v + a·Δ, |Δ| ≤ 1 с, и публикуется в диагностике.
– Ускорение по колёсам a_obs (МНК-наклон слитой скорости за 1 с) используется только в TRN.

9. ПОЛОЖЕНИЕ
Одометр s_odo — это s из EKF (ṡ = v). Дуга пути для главной антенны:
  s_M = s_off + δ_app + s_odo — до первой пачки GNSS;
  s_M = s_A + (1 + ε_p)·(s_odo − o_A) + c_TRN — после неё (s_A, o_A — положение и одометр последней пачки).
Выход: s_route = s_M + 9.873 м; (x, y, ψ) = RunPath.pose(s_route), z — высота пути.
– Выставка: s_off = медиана (s_proj − odo) по фиксам; курс — по базе master–rover 12.44 м; вне карты — ветвь кольца или мост.
– TRN: s_true = s_r + δ₀ + ε·(s_r − s_a), s_r = s_off + s_odo (сдвиг δ₀ и ошибка масштаба ε на сетке ±120 м × ±0.015); невязка r = a_obs − (ā_ng + c̄·g·γ(s_true + ℓ) − k_c·|κ(s_true + ℓ)|), уклон со сглаживанием 9 м, усечение 0.3 м/с², σ_r = 0.1 м/с², вес Δs/20 м; δ̂ = Eδ₀ + (s_r − s_a)·Eε, δ_app идёт к δ̂ не быстрее 1 м/с при σ_δ < 15 м.
– GNSS: медиана невязки пачки ν (RTK: гейт 2 м, разброс ≤ 1 м); k = σ_pr²/(σ_pr² + 1.2²), s_A = s_M(o) + k·ν; ε_p ← clip(ε_p + 0.3·ν/B; ±0.02) при базе B > 300 м; c_TRN = w·ι, w = σ_odo²/(σ_odo² + σ_δ²), где ι — расхождение TRN с продолжением якоря, σ_odo = 0.006·(s_odo − o_A).

10. СКОРОСТЬ — БЕЗ GNSS
Скорость строится только из тележек, контроллера и карты. В EKF нет измерения положения; связь с картой — только поиск уклона и кривизны по s_off + δ_app, куда якорь GNSS не входит. Поэтому /result/velocity с коррекцией и без неё совпадает побитно (юнит-тест; одинаковая v_rmse на кросс-валидации).
