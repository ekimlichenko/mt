ДОПУЩЕНИЯ, ОГРАНИЧЕНИЯ И КОНФИГУРИРУЕМЫЕ ПАРАМЕТРЫ
Подробно: docs/LIMITATIONS_ROADMAP.md §1, docs/PARAMETERS.md, docs/MODEL.md.

A. ДОПУЩЕНИЯ И ГРАНИЦЫ ПРИМЕНИМОСТИ

Маршрут и карта:
• Два маршрута, T2S и S2T (pathgraph maps/t2s.json, maps/s2t.json), в каждом один путь без съездов; направление фиксируется при выставке.
• Модель одномерная: состояние — путь s вдоль маршрута; курс, поперечное положение и z берутся из геометрии пути. Профиль z карты считается точным, коэффициенты уклона постоянны для режима движения.
• Параллельный путь в 4.2 м от pathgraph на части рейсов S2T (s ≈ 530–1140 м) покрыт только поперечной СКО pose_sigma_cross_m = 0.8 м.

Разворотные кольца:
• Рейс начинается перед кольцом одной конечной (s < 0) и заканчивается в кольце другой (s > L); вне карты около 20–30 % времени рейса.
• Геометрия колец (maps/loops.json) — медиана RTK-треков обучающих рейсов; используются только наблюдённые ветви.

Вагоны, колёса, масштаб K:
• Тележки передают скорость в км/ч; v = raw/K, K калиброван по RTK для каждого вагона. Внутри рейса K стабилен до ±0.3 %, между днями меняется на −0.66…+0.95 %.
• Тележки одного масштаба; вагон назад не едет (v ≥ 0).
• Управляющий вход один — позиция контроллера. Тормоза вне контроллера и загрузка не моделируются: их поглощают шум процесса, смещение модели b и адаптивные усиления.
• Без колёс модель держит путь 5–10 с (ошибка пути ≈5 % за 10 с).

Время:
• Все header.stamp входов, включая GNSS, — на одних часах вагона; метка выхода — копия метки входа, выход публикуется только на входное сообщение.

Политика GNSS (по разъяснениям организаторов):
• Скорость GNSS не использует: с коррекцией и без неё она совпадает побитово.
• GNSS служит для начальной выставки (RTK на старте гарантирован) и при gnss_aiding = true — для коррекции положения вдоль пути пачками фиксов. Если на старте GNSS нет, коррекция выключается и поздние фиксы игнорируются.

Соглашения выхода:
• /result/position — точка base_link в 9.873 м впереди главной антенны вдоль пути, z = z pathgraph, кадр map.
• /result/velocity — оценка на момент stamp − 0.09 с: подгонка под запаздывание эталонного twist, подобранная на единственном тестовом bag.

Известные слабые места (подробно — поле 7): выбор ветви хвоста кольца T одной пачкой GNSS; сдвиги часов GNSS ≈1 с; K по дням не оценивается онлайн; синфазное боксование и юз обеих тележек.

B. КОНФИГУРИРУЕМЫЕ ПАРАМЕТРЫ

Как задаются:
• Источник — dataclass Params в core/config.py: 199 параметров в 12 группах; config/params.yaml генерируется из него (tools/gen_params_yaml.py). Все read-only, задаются при старте узла.
• Аргументы launch: params_file (по умолчанию config/params.yaml пакета), output_frame, vehicle_id (по умолчанию 30618), use_sim_time (false), maps_dir, log_level. Других аргументов нет: gnss_aiding, output_* и прочие задаются только файлом или -p.
• Остальное — частичным yaml (только изменяемые параметры) или через --ros-args -p:
  ros2 launch tram_backup_odometry backup_odometry.launch.py params_file:=my_params.yaml
  ros2 run tram_backup_odometry backup_odometry_node --ros-args -p vehicle_id:=30618 -p gnss_aiding:=false
• Полный список (единицы, смысл, происхождение) — docs/PARAMETERS.md §5: https://github.com/ekimlichenko/mt/blob/main/docs/PARAMETERS.md

1) Начальная позиция
• Вручную не задаётся: выставка по GNSS в окне init_window_s = 3 с после первого фикса (не меньше init_min_fixes = 5), таймаут init_timeout_s = 10 с.
• Курс — по базе мастер–ровер (rover_ahead_m = 12.44 м, допуск init_baseline_tol_m = 2.5 м) или по движению; RTK-фиксы приоритетны, если их не меньше init_rtk_min_fixes = 3.
• Приоритет привязки: точка на карте (ближе init_onmap_dist_m = 3 м, затем init_near_dist_m = 8 м и init_far_dist_m = 30 м, курс в пределах init_heading_tol_deg = 60°) → ветвь кольца (ближе loop_max_dist_m = 8 м) → мост Эрмита до начала карты.
• Начальная СКО пути: sigma0_rtk_onmap_m = 3 м, loop_sigma0_m = 1.5 м, sigma0_bridge_t2s_m = 8 м, sigma0_bridge_s2t_m = 12 м; без RTK учитывается sigma0_nortk_m = 10 м.
• Нет фиксов за 10 с — счисление от точки старта в системе start.

2) Масса, радиус колеса, момент
• Отдельных полей нет сознательно: во входах нет массы, тока или момента — только позиция контроллера и скорости тележек. Цепочка a = (M(n,ω)·i·η/r_w − F_res)/m − g·γ не раскладывается на сомножители, и модель идентифицирует удельную силу a(n, v) как одну функцию позиции и скорости (ω = i·v/r_w).
• Масса и загрузка: отклонение действует как множитель тяги и торможения и поглощается адаптивными усилениями фильтра Калмана EKF (старт gain_tr = gain_br = 1.0, границы gain_min…gain_max = 0.8…1.3, блуждание gain_sigma = 0.002 1/√с) и смещением b (bias_tau_s = 10 с, bias_sigma = 0.05 м/с²).
• Радиус колеса: в тяге — внутри карты a(n, v), в одометрии — внутри K; wheel_k_30618 = 3.597, wheel_k_30639 = 3.59, wheel_k = 3.595 для неизвестного вагона (выбор по vehicle_id).
• Момент, передаточное число, КПД — внутри карты тяги a_tr = min(b0 + a0·n/(1 + max(v − v1, 0)/va), A0·min(1, vb/v)^pw) − r0: tr_b0 = 0.0968, tr_a0 = 0.1131, tr_A0 = 1.048 м/с²; tr_v1 = 3.49, tr_va = 6.9, tr_vb = 5.9 м/с; tr_pw = 0.571. Задержки привода: lag_tr_dead_s = 0.05, lag_tr_tau_s = 0.25, lag_br_dead_s = 0.15, lag_br_tau_s = 0.3 с.

3) Коэффициенты сопротивления
• Основное: res_r0 = 0.04 м/с². Аэродинамический член отдельно не выделяется: на выбеге сопротивление почти постоянно при v = 4–16 м/с.
• Кривые: −curve_k·|κ|, curve_k = 3.0 м²/с².
• Уклон: + c·g·γ, γ = dz/ds (окно grade_window_m = 31 м); grade_c_traction = −0.886, grade_c_brake = −0.812, grade_c_coast = −0.978, grade_c_hold8 = −0.812.
• Торможение: a_br = max(−(d0 + d1·|n|)·(1 − f·exp(−v/vf)), cap) − r0: br_d0 = 0.193, br_d1 = 0.1123 м/с², br_f = 0.327, br_vf = 2.98 м/с, br_cap = −1.7 м/с². Позиция −8: hold8_v = 2.5 м/с, hold8_low_acc = −0.85 м/с².

4) Пороги проскальзывания
• Согласие тележек: |F − R| ≤ max(agree_abs_mps = 0.2 м/с, agree_rel = 0.03·v); при расхождении берётся тележка, ближайшая к последней согласной скорости (slip_anchor_s = 3 с).
• Синфазный флаг: ускорение за slip_acc_win_s = 0.3 с выше slip_acc_flag = 2.5 м/с² или ниже −slip_dec_flag = −6 м/с²; удержание slip_hold_s = 1 с.
• Ограничитель темпа: acc_max = 1.8 м/с², dec_max_consistent = 6.0 м/с² (тележки согласны), dec_max_slip = 2.4 м/с² (прочие случаи).
• Отбраковка: wheel_stale_s = 0.5 с, spike_kmh = 4 км/ч.

5) Параметры фильтров
• EKF, состояние [v, b, g_tr, g_br, s]. Шум процесса по режимам, м/с²: sigma_a_traction = 0.11, sigma_a_coast = 0.16, sigma_a_brake = 0.085, sigma_a_brake_high = 0.43, sigma_a_hold8 = 0.6, sigma_a_nocmd = 0.5.
• Шум колёс: meas_sigma = 0.03 (обе тележки), meas_sigma_single = 0.045, meas_sigma_slip = 0.35 м/с.
• Шаг интегрирования max_step_s = 0.05 с. Гейт адаптации усилений gain_gate_sigma = 3σ; разрыв входа max_gap_s = 5 с.
• TRN (привязка по уклону): trn_enable = true, trn_sigma = 0.1 м/с², trn_apply_sigma_m = 15 м.
• GNSS-коррекция: гейт gnss_gate_rtk_m / gnss_gate_nortk_m = 2 / 6 м, σ gnss_sigma_rtk_m / gnss_sigma_nortk_m = 1.2 / 3 м, gnss_min_fixes = 2, gnss_drift_frac = 0.006.

6) Выходные параметры
• output_frame = map (также utm, start, enu); publish_on = all — выход на каждое сообщение колёс и команды.
• output_along_offset_m = 9.873 (base_link; 0 — главная антенна), output_z_offset_m = 0.0 (z pathgraph).
• output_velocity_delay_s = 0.09 с (0 — скорость на stamp); в офлайн-эмуляции чекера организаторов скорость RMSE 0.0335 м/с против 0.0566 без задержки.
• gnss_aiding = true; false — GNSS только в окне выставки (3D RMSE 1.11 против 7.16 м в эмуляции).
• С этими умолчаниями итоговый прогон чекера организаторов в Docker: скорость RMSE 0.0324 м/с, 3D RMSE 1.111 м.
